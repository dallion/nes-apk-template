# 金手指设计

## 格式与边界

Android 层解析 VCT、原始地址、Game Genie 和 CHT 分组，再向内核提交代码。

- `AAAA-L-VV`：L 为 1～4，数值按小端展开为逐字节写入。
- `AAAA:VV`：RAM 地址持续写入，ROM 地址读取替换。
- 六位或八位 Game Genie。
- CHT `[名称]` / `on=地址,字节;地址,字节`：字节按地址递增写入，多段代码共用一个开关。每段也可填写一条 Game Genie 码。命名选项可放在分组下。

导入读取 UTF-8 或 GB18030，文件上限 128 KiB；总展开数上限 256。无效分组或批量输入整体拒绝，避免只应用部分代码。`off=` 回滚动作不受支持。

内置空文件或纯注释文件表示没有预设；手工导入空文件仍报告没有有效代码。打包文件的选择和 ROM 摘要绑定遵循 [打包规则](packaging.md)。

### 单行代码

批量导入时，每行填写一条代码，后面可用空格分隔名称：

```text
0590-02-1F10 双字节写入
0534:FA 单字节写入
EAZTLA Game Genie 示例
```

`0590-02-1F10` 将 `10` 写入 `0590`，将 `1F` 写入 `0591`；`0534:FA` 将 `FA` 写入 `0534`。地址和值均为十六进制。示例用于说明格式，实际代码需匹配所用 ROM。

### CHT 分组

游戏目录中的 `.cht` 可按以下方式组织：

```ini
[连续写入]
on=0590,10,1F

[多段写入]
on=0590,10,1F;05D0,01,02

[组合补丁]
on=SXIOPO;EAZTLA

[角色数值]
角色一=051C,0B,04
角色二=051E,4F,0A
```

- 逗号后的字节从起始地址连续写入；`0590,10,1F` 对应 `0590=10`、`0591=1F`。
- 分号连接多个地址段或 Game Genie 码。同一行的全部代码共用一个开关。
- `on=` 使用分组名作为条目名称，导入后默认停用。
- 命名选项各自生成条目和开关，以上两项分别显示为“角色数值 / 角色一”和“角色数值 / 角色二”。

## 预设与持久化

可选的 `assets/game.cht` 让游戏代码随游戏目录打包，避免把游戏专用预设写死在 Kotlin 中。新增和导入默认停用。

金手指以 NCH1 格式存入 ROM 摘要目录下的 `cheats.bin`。一组选项的多条代码存于同一记录并共享开关，不混入 SaveRAM 或即时存档。

条目详情中的“编辑”可修改名称和整组代码；多段代码可分行填写，地址和值均为十六进制。保存时整体校验，非法代码不替换旧记录。编辑保留启用状态，已启用条目的修改会立即重新应用。

旧本地记录优先，内置预设不覆盖自定义内容和已有开关；显式恢复操作补齐缺少的预设。删除的预设不会因重启自动复活。启动、重置和读取即时存档后，重新应用启用列表。

## 内核适配

Android 层暂停模拟器后清空核心代码，再重建启用列表，以处理当前 FCEUmm 的索引和启用参数限制。

FCEUmm 使用明确的内部 `RAM:AAAA:VV` 指令进行周期写入，并在解析每个 token 时重置类型，避免混合代码继承错误类型。Mapper 246 的金手指 RAM 注册使用实际 SRAM 映射地址 `0x6800`。

停用只停止后续注入，不回滚已经改变的游戏数值。只需设置一次的代码应在生效后手动停用；代码注释不会触发自动停用。
